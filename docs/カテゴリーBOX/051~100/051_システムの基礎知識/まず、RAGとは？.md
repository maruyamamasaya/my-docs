RAG＝**Retrieval-Augmented Generation**の略。

日本語だと「検索拡張生成」って訳されることが多い。

ざっくりいうと：

> 「AIが答える前に、必要な情報を検索してきて、その情報をヒントにして答えを作る」

ってやり方！

---

# 🤔 なぜRAGをやるの？

普通のLLM（大規模言語モデル）は、  
**訓練データに無かったことを答えられない** or **間違ったことを勝手に作っちゃう（ハルシネーション）**リスクがある。

でもRAGを使うと、

- **最新の自社データ**（ナレッジベース・マニュアル・顧客情報）
    
- **外部の最新情報**（ニュース・論文）
    

を**検索して持ってきて、それをもとに回答する**から、

✅ 正確さが上がる  
✅ 自社専用の賢いチャットボットが作れる  
✅ モデル自体をファインチューニングしなくても済む

みたいなメリットがある！

---

# 🛠️ BedrockでRAGをやる手順（全体像）

簡単に流れを言うとこう👇

1. **知識データベースを準備する**  
    　例：社内文書、FAQ、商品マニュアルなど
    
2. **そのデータをベクトル化する**（＝検索しやすくする）  
    　→ 文章を「意味の方向」で表した数値に変換（埋め込み＝embedding）
    
3. **ベクトルDBに保存する**  
    　→ たとえばAmazon OpenSearch Serverless、Pinecone、Chromaなどを使う
    
4. **ユーザーの質問もベクトル化して近い文書を探す**  
    　→ 「この質問に似た内容はどれ？」って検索する
    
5. **見つかった情報をAIモデルに渡して回答を生成させる**  
    　→ つまり「この資料を参考にして答えてね」と指示を出す
    

---

# ✨ Bedrock特有のポイント

- Bedrockでは**埋め込み用モデル**（例：Titan Embeddings）も提供されている
    
- **生成用モデル**（例：Claude 3やTitan Text）も選べる
    
- AWS公式の「Knowledge Bases for Amazon Bedrock」というサービスを使うと、  
    **このRAGのフローをほぼ自動化できる**！
    
- しかも、**S3にドキュメントを置くだけでOK**みたいなシンプル設計もできる
    

---

# 🎯 まとめ図

```
[ ユーザーの質問 ]
         ↓
 [ 質問をベクトル化 (Embedding) ]
         ↓
 [ ベクトルDBで検索 ]
         ↓
 [ 関連文書を取得 ]
         ↓
 [ 文書を参考にプロンプト作成 ]
         ↓
 [ BedrockのAIモデルに渡して回答生成 ]
         ↓
 [ ユーザーに回答 ]

```

# 💡 例えるなら

普通のAI  
→ 「記憶だけで答える人」

RAG  
→ 「まず本棚を調べて、参考文献を見ながら答える人」

って感じ！
